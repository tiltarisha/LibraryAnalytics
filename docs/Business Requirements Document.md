# Business Requirements Document
## Проект: LibraryAnalytics

## 1. Цель проекта

Разработать информационно-аналитическую систему для библиотечного сервиса, которая позволяет:
- хранить структурированные данные о книжном фонде, читателях и выдачах
- анализировать активность читателей и популярность книг/жанров
- отслеживать просрочки и штрафы
- визуализировать ключевые метрики для принятия управленческих решений

## 2. Бизнес-контекст

Библиотека ведёт учёт книжного фонда и выдач читателям, но не имеет единого инструмента для анализа собственной деятельности: сложно быстро понять, какие книги наиболее востребованы, какие читатели наиболее активны и насколько велика проблема просрочек.

## 3. Заинтересованные стороны (Stakeholders)

| Роль | Интерес в проекте |
|---|---|
| Администратор библиотеки | Оперативный обзор состояния фонда и читательской активности |
| Заведующий библиотекой | Управленческие решения: закупка книг, работа с должниками |
| Аналитик/разработчик | Демонстрация компетенций (SQL, Python, BI) |

## 4. Цели и задачи

| Цель | Задача |
|---|---|
| Понимать спрос на книги | Определять топ книг и жанров по числу выдач |
| Оценивать читательскую активность | Выявлять самых активных читателей, сегментировать по давности регистрации |
| Контролировать дисциплину возвратов | Считать долю просроченных возвратов, средний срок пользования книгой |
| Отслеживать финансовую дисциплину | Считать сумму начисленных и неоплаченных штрафов |
| Видеть динамику | Отслеживать изменение числа выдач по месяцам |

## 5. Границы проекта

**Входит в объём:**
- проектирование и создание БД (MS SQL Server)
- генерация тестового набора данных
- набор аналитических SQL-запросов
- расчёт метрик и визуализация средствами Python
- интерактивный дашборд в Power BI

**Не входит в объём:**
- пользовательский интерфейс (веб/десктоп-приложение) для сотрудников библиотеки
- интеграция с внешними системами (например, каталогами других библиотек)
- аутентификация и разграничение прав доступа
- автоматическое уведомление читателей о просрочках

## 6. Функциональные требования

- FR1: Система хранит данные о книгах, авторах, жанрах, издательствах
- FR2: Система хранит данные о читателях и их регистрации
- FR3: Система фиксирует выдачи книг (дата выдачи, срок, фактический возврат, статус)
- FR4: Система рассчитывает штрафы за просроченный возврат
- FR5: Система предоставляет аналитические запросы по книгам, жанрам, читателям, срокам
- FR6: Дашборд визуализирует ключевые метрики и поддерживает фильтрацию по жанру

## 7. Нефункциональные требования

- NFR1: Скрипты воспроизводимы — генерация тестовых данных детерминирована (фиксированный seed)
- NFR2: Данные корректно поддерживают кириллицу (UTF-8/Unicode)
- NFR3: SQL-запросы используют индексы на часто фильтруемых полях (reader_id, book_id, genre_id)
- NFR4: Экспортируемые для BI данные хранятся в человекочитаемом формате (csv, utf-8-sig)

## 8. Критерии успеха

- БД спроектирована в 3НФ, связи корректны, тестовые данные наполнены без ошибок целостности
- Аналитические запросы покрывают все заявленные в разделе 4 задачи
- Дашборд отображает все ключевые метрики и поддерживает базовую интерактивность (фильтры)

## 9. Допущения и ограничения

- Используется тестовый набор данных, а не реальные данные библиотеки
- Срок выдачи книги фиксированный — 14 дней
